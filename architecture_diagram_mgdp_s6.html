Key Data Flows

🔋 OBD Telemetry Pipeline

1
ELM327 adapter connects via BLE/BT. AT commands configure ISO-TP headers for target ECU (e.g. ATSH 781 for MG ZS EV BMS).
2
UDS 0x22 queries (ReadDataByIdentifier) sent every 2s. Multi-frame ISO-TP responses reassembled into raw bytes.
3
EV profile parser decodes raw bytes → typed metrics: SOC %, voltage, current, cell delta mV, SOH %, temperature.
4
GPS position merged: elevation, road grade computed from altitude delta over 50m. GPS speed fills in when OBD speed PID unavailable.
5
Analytics calculator updates trip distance, average speed, peak speed, driving score, efficiency score, harsh events.
6
SOC Predictor (20-sample rolling window) computes %-per-km depletion rate → predicted km to user's charge threshold.
7
Snapshot upserted to Supabase obd_sessions (fire-and-forget, non-blocking) and rendered in UI.

⚡ Charging Map Pipeline

1
User pans map or searches location. Flutter app captures GPS coordinates, rounded to 4 decimal places (~11m) to prevent duplicate API calls.
2
Request sent to Cloud Run API: GET /api/v1/chargers?lat=&lng=&radius=. JWT Bearer token from Supabase auth included.
3
API middleware validates JWT. Extracts user_id. Checks stale-while-revalidate cache (5-min TTL per lat/lng bucket).
4
On cache miss: parallel async fetch from HERE EV Search + OpenChargeMap + OCPI operators. 8s timeout per source.
5
Results deduplicated by location (100m radius), normalized to GeoJSON feature collection, cached, returned.
6
Flutter renders charger markers on FlutterMap. Cluster markers at zoom < 12. Detail sheet on tap with connector types, availability.
7
Route planner filters chargers reachable within current SOC range prediction before rendering.
